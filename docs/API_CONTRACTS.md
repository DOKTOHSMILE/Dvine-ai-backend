# API

Bearer token from `POST /api/v1/sessions`. The server decides the user. A body `userId` is not accepted.

`POST /api/v1/desk-rooms/{id}/commands`

```
{
  "requestId": "client-token-8-to-80",
  "text": "Should we plan this?",
  "activeAgent": "obi"
}
```

`activeAgent` is optional (`obi` or `ivie`). It is only the face already on screen. Naming someone in the text overrides it.

Each user may send `dvine.commands-per-minute` new questions a minute (default 20, `DVINE_COMMANDS_PER_MINUTE`); over that the answer is `429` and an audit event is written. A replay of a request id returns the stored task and is not counted.

The phone (M7, `DeskClient`) creates one desk room on first use and keeps its id, makes a new one if the server answers `404`, signs in again once on `401`, and reads `GET /api/v1/tasks/{id}/events?after=0` after the command returns. It plays `THINK` and `SAY` events with a persona; `STATUS` events stay silent.

`GET /api/v1/tasks/{id}`

`GET /api/v1/tasks/{id}/events?after={eventId}`

Event:

```
{
  "eventId": 1,
  "taskId": "...",
  "state": "EXECUTING",
  "agent": "ivie",
  "cue": "SAY",
  "message": "short line",
  "createdAt": "2026-01-01T00:00:00Z"
}
```

`cue` is `STATUS`, `THINK`, or `SAY`. The phone switches to `agent` on `THINK` and `SAY` and speaks only `SAY`. `STATUS` is the task machine, not a second face.

WebSocket `/ws/tasks`: first text frame `{"op":"auth","token":"..."}`, then `{"op":"subscribe","taskId":"...","after":0}`. Unauthenticated sockets are closed. The token is not logged.

Task states, in order: RECEIVED, AUTHORIZED, UNDERSTOOD, PLAN_CREATED, POLICY_CHECK, QUEUED, EXECUTING, VERIFYING, COMPLETED.

## Offline knowledge and learning (Track M ↔ Track S)

Implemented (`ai.dvine.knowledge`, `ai.dvine.learning`, migration V2). The Android client calls these when `api_base` is set. The served pack is `src/main/resources/knowledge/base_knowledge.json`; copy it from the Android repo (`tools/pack_source.py` output) when the pack version changes.

`GET /api/v1/knowledge/manifest` (no user data, may be public):

```
{ "version": 2, "sha256": "<64 hex of the pack body>", "size": 25898, "url": "/api/v1/knowledge/pack/2" }
```

`GET /api/v1/knowledge/pack/{version}` returns the pack JSON (schema in handbook §7). The phone installs it only if `version` is newer and the sha256 matches.

`POST /api/v1/learning/sync` (authenticated; the user comes from the session, never the body):

```
{ "schemaVersion": 1, "deviceId": "uuid",
  "entries": [ { "id": "uuid", "kind": "TAUGHT_FACT|CORRECTION|UNANSWERED|FEEDBACK",
                 "text": "my city", "answer": "Sapele", "createdAt": 1793007000000 } ] }
```

Response `{ "accepted": ["id", ...], "rejected": [ { "id": "...", "reason": "..." } ] }`. Repeated ids are accepted again without duplicating rows. Entries land owner-scoped in a review queue (`PENDING`); nothing is promoted into a shared pack without review and de-identification. Personal facts stay in that user's private memory.

Offline wording the server may reuse when its own store is unreachable: "I'm unable to connect to my database to get more information. Please connect to the internet and ask me again."


## Episodes: the long-term memory archive and consolidation (secondary engine jobs)

Implemented (`ai.dvine.episodes`, migration V4). The phone's engine keeps only a short episode buffer and runs everything real-time itself (handbook §27). The server archives episodes and consolidates them.

`POST /api/v1/episodes/sync` (authenticated, owner from the session):

```
{ "schemaVersion": 1, "deviceId": "uuid",
  "episodes": [ { "id": "ep-…", "kind": "ACTION|SCENE|TOUCH|PERSONA|FAILURE|LEARN|TALK",
                  "tag": "pose:pushups", "summary": "moved into pushups",
                  "importance": 0.4, "occurredAt": 1793007000000 } ] }
```

- Up to 200 per call. The response is `{ "accepted": [...], "rejected": [ { "id", "reason" } ] }`.
- A tag must look like `group:value`, in lower case.
- Unknown kinds, malformed tags and anything that looks like a secret are rejected.
- Replays are accepted without new rows. Summaries are generated by the phone and never carry the user's words.

`GET /api/v1/episodes/profile` (authenticated) returns the consolidation over the last 90 days:

```
{ "schemaVersion": 1, "episodes": 42, "recentFailures": 1,
  "favourites": { "pose": ["pushups", "cartwheel"], "scene": ["morning workout"], "touch": ["left hand"] } }
```

Up to three per group, most frequent first. The phone treats these as hints only ("what do I like?").

## Device sign-in (no secret in the app)

`POST /api/v1/devices/register` `{ "deviceId": "uuid" }` → `201 { "userId", "deviceSecret" }`. Once per device; a second registration of the same `deviceId` is `409`. Rate-limited per client address (`dvine.device-registrations-per-hour`, default 10; `429` when exceeded). Turn off with `DVINE_DEVICE_REGISTRATION=false`. Behind a reverse proxy, enable forwarded headers (`server.forward-headers-strategy=framework`) so the limit sees the phone's address.

`POST /api/v1/sessions/device` `{ "deviceId", "deviceSecret" }` → `{ "token", "userId", "expiresAt" }` (12 hours). Wrong secret is `401`. The phone keeps the device secret encrypted with an Android Keystore key and signs in again when the token expires.
